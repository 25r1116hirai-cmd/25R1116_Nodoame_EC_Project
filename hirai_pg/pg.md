# ECサイト要件定義メモ（検討・決定事項）

## A. 商品管理
商品の見せ方と管理方法を定義します。

| 項目 | 選択肢 | メリット / デメリット | 決定案 |
| :--- | :--- | :--- | :--- |
| **カテゴリー分け** | 分類あり / フラット | 【あり】探しやすさ向上。 【なし】開発・登録が楽。 | [ ] |
| **おすすめ基準** | 手動フラグ / 最新順 | 【手動】戦略的に売れる。 【最新】運用が自動。 | [ ] |
| **商品画像枚数** | 1枚のみ / 複数枚 | 【複数】情報量が増えCVR向上。 【1枚】撮影・管理が楽。 | [ ] |

- **メモ:** 商品数が30点を超えるなら「カテゴリー分け」推奨。工芸品などは裏面や細部も見せたいため「複数枚」が望ましい。

---

## B. 在庫・購入制限
売り切れリスクやトラブル防止のルールを定義します。

| 項目 | 選択肢 | メリット / デメリット | 決定案 |
| :--- | :--- | :--- | :--- |
| **個数制限** | なし / あり(上限n個) | 【あり】転売・買占め防止。 【なし】客単価向上。 | [ ] |
| **在庫戻し** | 手動 / 自動 | 【自動】在庫ズレがない。 【手動】実装コスト大幅減。 | [ ] |

- **メモ:** キャンセル頻度が低い初期運用なら「手動」でコストを抑えるのも手。

---

## C. ユーザー（注文者）情報
購入フローの摩擦（面倒くささ）を左右します。

| 項目 | 選択肢 | メリット / デメリット | 決定案 |
| :--- | :--- | :--- | :--- |
| **会員登録** | 必須 / 任意(ゲスト可) | 【必須】リピート施策。 【任意】離脱率低下。 | [ ] |
| **配送先指定** | 自宅のみ / 別途指定可 | 【別途】ギフト需要に対応。 【自宅】実装がシンプル。 | [ ] |

- **メモ:** 工芸品やお菓子はギフト需要が高いため、住所入力の分離（送り主・送り先）は検討の価値あり。
